# 📝 프롬프트 관리 프로그램

자주 사용하는 AI 프롬프트를 저장하고 관리하는 파이썬 프로그램입니다.
https://github.com/vlfgl/python

## 🌟 주요 기능
1. 프롬프트 목록: 저장된 모든 프롬프트의 제목을 한눈에 확인
2. 프롬프트 추가: 새로운 프롬프트의 제목, 내용, 카테고리를 입력하여 저장
3. 프롬프트 상세보기: 특정 프롬프트의 전체 내용과 상세 정보를 확인
4. 카테고리별 조회: 원하는 카테고리에 속한 프롬프트만 조
5. 프롬프트 검색: 키워드를 입력해 제목이나 내용에 해당 단어가 포함된 프롬프트를 찾습니다.
6. 즐겨찾기 설정/해제: 자주 쓰는 프롬프트를 즐겨찾기에 추가하거나 해제
7. 즐겨찾기 목록: 즐겨찾기로 설정된 프롬프트만 따로 모아 빠르게 확인

## 🚀 사용 방법
1. 파이썬 환경이 설치되어 있어야 합니다.
2. 터미널에서 `python prompt_manager.py`를 실행합니다.
3. 화면에 나오는 메뉴 번호를 입력하여 기능을 사용합니다.

## 📁 등록된 프롬프트 카테고리
프롬프트를 추가할 때 목적에 맞게 다음 6가지 카테고리로 분류하여 관리할 수 있습니다.

1) 텍스트 생성: 블로그 글 작성, 요약, 번역 등 텍스트 기반 결과물을 위한 프롬프트
2) 이미지 생성: 미드저니, DALL-E 등 이미지 생성 AI를 위한 프롬프트 (예: 썸네일 생성)
3) 영상 생성: 비디오 생성 AI에게 지시할 때 사용하는 프롬프트
4) 페르소나: AI에게 특정 역할(전문가, 튜터, 마케터 등)을 부여하는 프롬프트
5) 자동화: 업무 자동화, 데이터 분석 및 처리 등을 위한 프롬프트
6) 기타: 위 분류에 속하지 않는 다양한 프롬프트 (번호 입력 없이 엔터를 누르면 기본값으로 설정됨)

## 📐 설계 및 구현 근거

### 1. 함수 분리 설계 근거
본 프로그램은 단일 함수에 코드를 집중시키지 않고, 역할과 책임에 따라 함수를 분리했습니다.
- `show_menu()`: 사용자 UI 출력 및 입력 처리 담당
- `add_prompt()`, `search_prompt()` 등: 각 기능별 비즈니스 로직 담당
- **분리 이유**: 코드의 가독성을 높이고, 특정 기능에 버그가 발생했을 때 해당 함수만 수정하면 되도록 유지보수성을 극대화하기 위함입니다.

### 2. 커밋(Commit) 기준 및 메시지 규칙
- **커밋 단위**: '프롬프트 추가 기능 완료', '검색 기능 완료' 등 하나의 기능(Feature)이 정상 작동할 때마다 커밋을 진행했습니다.
- **메시지 규칙**: 
  - `feat:` 새로운 기능 추가
  - `docs:` README 등 문서 수정
  - `chore:` 주석 수정, 테스트 등 자잘한 작업

### 3. 데이터 구조 선택의 장단점
- **리스트(List) + 딕셔너리(Dictionary) 조합 사용**
- **장점**: 리스트는 순서가 보장되어 목록을 출력할 때 유리하며, 딕셔너리는 `title`, `content` 등 키(Key)값으로 데이터에 직관적으로 접근할 수 있어 프롬프트 관리에 최적화되어 있습니다.
- **단점**: 데이터가 수만 개 이상으로 커질 경우, 리스트를 순회하며 검색하는 속도가 느려질 수 있습니다.

### 4. 메인 루프 설계 의도 및 종료 조건
- `while True:`를 사용하여 무한 루프를 설계했습니다.
- **설계 의도**: 사용자가 한 번의 작업을 마친 후 프로그램이 꺼지지 않고, 계속해서 다른 메뉴를 이용할 수 있도록 하기 위함입니다.
- **종료 조건**: 사용자가 메뉴에서 '종료(예: 7번)'를 입력했을 때 `break` 문을 호출하여 루프를 탈출하고 프로그램을 안전하게 종료합니다.

### 5. 브랜치 전략 및 병합 시점
- **분리 기준**: `main` 브랜치는 항상 실행 가능한 안정적인 상태를 유지하고, 새로운 기능(예: 목록 조회)을 개발할 때는 `feature-update` 등 별도의 브랜치를 생성하여 작업했습니다.
- **병합 시점**: 해당 브랜치에서 기능 구현과 테스트가 완전히 끝난 후 `main` 브랜치로 `merge` 하였습니다.

### 6. 데이터 영속화 설계 근거
- 현재는 메모리(리스트)에만 저장되지만, 향후 영속화를 진행한다면 **JSON 파일 형식**을 사용할 계획입니다.
- **설계 근거**: 파이썬의 딕셔너리 구조와 1:1로 완벽하게 호환되며, 사람이 읽고 쓰기 편하고, 다른 프로그램(웹/앱)과 데이터를 주고받기 가장 좋은 표준 포맷이기 때문입니다.

### 7. 중복 제목 발생 시 처리 규칙
- **규칙**: 프롬프트 추가 시 기존 목록에 동일한 제목이 있는지 검사합니다.
- **처리 방식**: 중복된 제목이 발견되면 기존 데이터를 보호하기 위해 **'덮어쓰기 거부 및 추가 취소'** 처리를 하고 사용자에게 경고 메시지를 출력합니다.

### 8. 병합 충돌(Merge Conflict) 해결 절차
협업 중 충돌이 발생할 경우 다음 순서로 해결합니다.
1. **원인 분석**: `git status`로 충돌이 발생한 파일을 확인합니다.
2. **해결**: VSCode에서 충돌 파일(Merge Changes)을 열어 `<<<<<<< HEAD` 등의 마커를 확인하고, 남길 코드를 선택하여 수정합니다.
3. **검증**: 코드가 정상 작동하는지 테스트한 후, `git add`와 `git commit`을 통해 충돌 해결을 완료합니다.

### 9. 카테고리 변경 시 수정 지점
- 새로운 카테고리를 추가하거나 이름을 변경하려면, `prompt_manager.py` 파일 상단에 정의된 `CATEGORIES` 리스트 변수만 수정하면 됩니다. (코드 내 주석으로 명시함)
